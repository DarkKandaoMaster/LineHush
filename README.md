# LineHush

Windows 本地优先图文日记编辑器。Tauri 2 + React + TypeScript，正文只有纯文本和图片。

## 启动

- 开发：`pnpm tauri dev`
- 检查前端：`pnpm build`
- 构建可独立启动的程序：`pnpm tauri build --no-bundle`；`pnpm tauri build` 只生成 NSIS 安装包（`bundle.targets = ["nsis"]`），位于 `src-tauri/target/release/bundle/nsis/LineHush_<版本>_x64-setup.exe`。安装包为当前用户注册 `.hush` 文件关联（`bundle.fileAssociations`，类型名“LineHush 日记”，图标沿用程序图标），卸载时移除。
- 程序位置：`src-tauri/target/release/LineHush.exe`。运行需要 Windows WebView2（当前机器已安装）。
- Rust 依赖 `rusqlite`（`bundled`，自带 SQLite，无需系统安装）与 `sha2`（图片 id）。
- 构建不需要手动把 `rc.exe` 加入 PATH：Tauri 的构建脚本（`tauri-winres` → `embed-resource`）会通过注册表 / Visual Studio 安装信息自动找到 Windows SDK 的 `rc.exe`。2026-10-03 在未进入 VS 开发者环境、PATH 中没有 `rc.exe` 的 PowerShell 和 Git Bash 中强制重跑构建脚本均通过。若某个环境报 “RC.EXE” 相关错误，再临时把 `C:\Program Files (x86)\Windows Kits\10\bin\10.0.26100.0\x64` 加入 PATH。

## 使用

直接输入正文，按 Ctrl+S 或“保存”写入 `.hush` 文件；未命名文档会先弹出另存为。日记文件只在保存或另存为时改变。停止输入约 650 毫秒后，未保存的修改会暂存到本机工作副本（不改动日记文件）；启动时像记事本一样默认新建一个未命名文档，不重新打开上次的文件；只有程序意外退出留下未保存的修改时，再次启动才重新打开原文件并恢复这些修改、标记为未保存并提示“已恢复未保存的修改。”（保存成功后提示消失）；若上次打开的文件已被移走、改名或无法打开，暂存的修改作为未命名文档恢复，并提示原文件无法打开及原因。右下角显示“尚未保存”“已保存”“保存失败”或“暂存失败”，标题栏和工具栏的“● ”表示有未保存的修改。有未保存的修改时关闭窗口、新建或打开，会询问“保存 / 不保存 / 取消”（Esc 等于取消）；选“不保存”丢弃修改，文件保持上次保存的样子；保存失败时保留窗口和当前内容。

出错时横幅用中文说明原因，并在括号中附上系统或 SQLite 的原始信息便于排查，例如“保存失败：磁盘已满（database or disk is full）”。原因分为：磁盘已满、没有写入权限或文件无法访问、不是有效的 .hush 文件或文件已损坏、文件正被其他程序占用、文件不存在、没有访问权限，其余为“读写失败”。

图片可以通过“插入图片”、粘贴剪贴板中的图片或拖入文件添加。支持 JPG、PNG、GIF、WebP、BMP（由 Cargo `image` 启用的格式决定）；单个文件不超过 256 MB，解码上限 16000 像素边长、256 MB 内存。无法插入时提示文件名和原因：“不支持的图片格式”“图片已损坏或无法解码”“图片尺寸过大（上限 16000 像素）”（或“解码所需内存超过 256 MB”）、“图片文件过大（上限 256 MB）”。多图同次插入形成图片组，选中图片组后插入会追加。真实空行阻止组自动合并。双击缩略图查看原图，预览中“保存原图”把文件中的原图按原字节写出，Esc 关闭。选中组后 Delete / Backspace 删除，Ctrl+Z 撤销。

Enter / Shift+Enter 产生一个逻辑换行，没有段落间距。连续和末尾空行保留。网页粘贴只取纯文本，不解析 Markdown。Tab 插入制表符。Ctrl+Z 撤销，Ctrl+Y 或 Ctrl+Shift+Z 重做。

| 操作   | 快捷键       |
| ------ | ------------ |
| 新建   | Ctrl+N       |
| 打开   | Ctrl+O       |
| 保存   | Ctrl+S       |
| 另存为 | Ctrl+Shift+S |

双击 `.hush` 文件（或 `LineHush.exe <文件>`）用 LineHush 打开。LineHush 同时只运行一个进程、一个窗口（`tauri-plugin-single-instance`）：已在运行时再次双击，新进程把参数交给已打开的窗口后立即退出；是当前文件就只把窗口还原并置顶，是其他文件就和“打开”一样先询问未保存的修改再打开，没有参数时只置顶。程序未运行时双击，直接打开该文件；但若上次留有未保存的修改，先恢复它们，再询问“保存 / 不保存 / 取消”后打开双击的文件。参数可带引号或为相对路径，按启动目录解析后规范化再比较。

“导出”支持纯文本和 HTML。TXT 使用图片文件名占位；HTML 把正文引用的原图写到同目录 `附件` 文件夹（`<id 前 12 位>-<原文件名>`），与 HTML 一起移动即可阅读。

## 文件与恢复

- `.hush` 是单个 SQLite 文件，正文和原图都在其中，格式说明保存在本地 `docs/file-format.md`（未纳入仓库）。移动或备份日记只需这一个文件。打开文件时只对正文做结构反序列化（拒绝未知字段和节点）。
- 原图按字节原样保存，以 SHA-256 为 id，同一张图只存一份。缩略图在打开时现场生成，只缓存在内存，不写入文件。
- 保存在一个事务里写入正文和自上次保存以来新导入的图片，不重写已有图片。正文删除的图片在会话内仍可撤销找回；关闭窗口或切换文档时按已保存的正文删除未引用的图片并回收空间。这一清理只是尽力而为：文件所在 U 盘已拔出、文件损坏或只读时，关闭、新建、打开照常完成，图片留在文件里等下次清理；切换文档时横幅提示“上一个文件的未引用图片未能清理：<原因>”，关闭窗口时直接关闭、不提示。工作副本若未能清空（例如被其他程序占用），关闭照常进行，下次启动会把这些修改当作未保存的修改恢复。
- 另存为先写出临时文件再替换目标，原文件不变。不再生成 `.bak` 备份。
- 文件只由本程序读写；打开期间被其他程序改动会在下一次保存时被覆盖。
- 未保存的修改和新导入的图片暂存在 `%APPDATA%\com.kandao.linehush\working.hush`（工作副本，与文档同格式，不是用户文档），保存、关闭或切换文档后清空；未命名文档的工作副本就是草稿。同目录 `recovery.json` 只记录工作副本中的暂存属于哪个文件：正常启动一律新建未命名文档并把它写成 `{path:null}`；只有工作副本留有暂存时才按路径重新打开原文件并恢复暂存的修改；该文件打不开时，有暂存则保留工作副本作为未命名草稿（只在原文件中的图片显示“无法显示此图片”），没有暂存则新建草稿。日记内容不会上传服务器。
- 当前为单窗口单文档（多窗口尚未实现）。第二个进程由 single-instance 插件转发参数后退出；数据目录的 `session.lock` 仍作兜底，万一第二个进程没被转发而取不到锁，会弹出“LineHush 已在运行……”提示框后退出，不再静默崩溃。

## 验证

- `pnpm test`（26 项）：Node 24 直接运行 `tests/*.test.mjs`，导入 `src/core/*.ts`（类型剥离，无构建步骤）；覆盖文档格式、换行、导出转义与附件命名、暂存队列、会话订阅，以及保存（失败提示以“保存失败：”开头）/ 未命名另存为 / 恢复标记与提示（含原文件丢失）和关闭、新建、打开前的“保存 / 不保存 / 取消”询问，外部请求打开文件（双击）时的询问与“导入中先等待”，关闭时 `close_document` 出错仍销毁窗口，以及切换文档时显示 Rust 返回的“未能清理”提示。
- `pnpm test:browser`（12 项，`tests/browser/*.spec.ts`，自动启动或复用 `pnpm dev`）：通过本机 Edge 验证编辑与粘贴、初始化、只暂存不写文件与 Ctrl+S 保存后的光标及撤销、暂存失败提示、文件切换、保存故障与重试、关闭询问（取消 / Esc / 不保存 / 保存）、导出，以及按 id 读取图片和保存原图。会话集成测试替换原生 IPC 边界，编辑器与暂存队列使用真实实现。
- `cargo test --manifest-path src-tauri/Cargo.toml --offline --locked`（26 项）：启动参数中 `.hush` 路径的识别（引号、相对路径、大小写）；错误信息中的路径去掉 `\\?\` 前缀（`fsx.rs`）；SQLite 与文件系统错误的中文翻译（`errors.rs`）；图片错误分为不支持的格式 / 已损坏 / 尺寸或内存超限，以及 256 MB 文件上限（`images.rs`）；文件正文损坏或整个文件被改成乱码时关闭仍成功、工作副本被占用无法清空时关闭仍成功、从损坏的文件新建 / 打开仍成功并返回提示；打开不存在 / 非 SQLite / 其他程序的 SQLite 文件和保存到只读文件时的中文原因；真实临时目录中的 `.hush` 文件结构与空行往返、只在保存时改文件、正常关闭后启动新建未命名文档且 `recovery.json` 变为 null、崩溃后恢复暂存到原文件（含原文件被移走后作为未命名草稿恢复、`recovery.json` 损坏时作为草稿恢复）、原图逐字节与去重、草稿恢复与另存为（含另存为当前文件、带上未保存图片）、关闭与切换时丢弃修改并清理、读入结构检查、打开失败、导出与缩略图、并发缩略图只解码一次。
- `pnpm dev` 运行时，先 `cargo build --manifest-path src-tauri/Cargo.toml --offline --locked`，再 `node tests/native.mjs`：隔离测试数据，用真实 WebView2 检查 18 项：草稿崩溃恢复、中文换行、未命名保存走另存为、只在保存时写文件（暂存后用户文件字节与修改时间不变）、保存写入正文与新图片、撤销重做、多图原图（`images` 表与 `export_image` / HTML 导出均与源图逐字节相等）、另存为当前文件、关闭弹窗（Esc / 取消保留窗口且焦点回到编辑区、弹窗期间 Ctrl+S 无效、不保存后文件保持原样）、关闭清理（未引用图片关闭后不在 `images` 表中）、文件结构（SQLite 文件头、PRAGMA、无 `-journal` / `-wal` / `.tmp` 残留，数据目录只有 `recovery.json`、`session.lock`、`working.hush`）、正常关闭后新建（重启后标题为“未命名”、无恢复提示、`recovery.json` 的 path 为 null，再双击文件才打开它）、关闭时保存、崩溃恢复（`taskkill /F` 后重启恢复暂存正文与图片、标记未保存，用户文件不变；Ctrl+S 后恢复提示消失）、保存后重启仍为未命名、原文件丢失恢复（暂存后强杀、移走用户文件再重启：出现提示、正文为暂存内容、未保存、标题为“● 未命名”，原文件中的图片显示占位，`recovery.json` 的 path 为 null）、第二实例转发（有未保存修改时再启动一个带 `.hush` 参数的进程：第二个进程退出码 0，原窗口弹出询问，选不保存后标题变为该文件；用相对路径从另一目录再次启动同一文件不弹窗、不重开；无参数启动只置顶）和启动参数打开文件（无暂存时带参数启动打开参数文件并写入 `recovery.json`；有崩溃暂存时先恢复并询问，不保存后打开参数文件）。脚本用 Node 内置 `node:sqlite` 只读检查文件；系统“保存日记”对话框通过 Win32 消息填写文件名并确认（PowerShell 内联 C#），只写入 `test-results/`；这会更新 Windows 为 `LineHush.exe` 记住的上次保存目录。`src-tauri/capabilities/default.json` 中的 `core:window:allow-close` 只为该脚本模拟关闭窗口所需。设置 `LINEHUSH_TEST_DATA_DIR` 后数据目录改到该处，标识符也改为 `com.kandao.linehush.test`（单实例互斥与 WebView2 配置目录都按标识符区分），测试不访问个人日记，也不会把参数转交给正在使用的 LineHush。
- `pnpm tauri build --no-bundle` 后运行 `node tests/native.mjs --release`：对独立 Release 程序执行同样的桌面回归，不需要开发服务器。
- 测试记录都放在 `test-results/`：`native-*`（桌面回归）、`playwright/`（Playwright 输出，每次运行前只清空这个子目录）。

自动化输入不等于真实中文输入法候选操作。交付前仍建议用自己的输入法连续写一段，测试候选确认、修改拼音、图片边界移动以及撤销的主观手感。第一版暂无全文查找、文档标签页或侧栏。
